URL

Livewireでは、コンポーネントのプロパティの値をURLのクエリ文字列（URLの?以降の部分）に保存できます。これにより、ページの状態を簡単に共有したりブックマークしたりできるようになります。

例えば、$searchプロパティの値をURLに含めると、https://example.com/users?search=bobのようなURLが生成され、このURLをブックマークしたり共有したりすると、その状態を再現できます。この機能は特に検索フィルタ、ソート条件、ページネーションなど、ユーザーが設定した状態を保持したい場合に役立ちます。

基本的な使い方​

まずは、URLとの連携機能を実装する具体例を見てみましょう。以下は、ユーザー名で検索できるShowUsersコンポーネントの実装例です：

<?php

namespace App\Livewire;

use Livewire\Attributes\Url;
use Livewire\Component;
use App\Models\User;

class ShowUsers extends Component
{
    public $search = '';

    public function render()
    {
        return view('livewire.show-users', [
            'users' => User::search($this->search)->get(),
        ]);
    }
}
<div>
    <input type="text" wire:model.live="search">
    <ul>
        @foreach ($users as $user)
            <li wire:key="{{ $user->id }}">{{ $user->name }}</li>
        @endforeach
    </ul>
</div>

この実装では、テキスト入力欄にwire:model.live="search"を適用しています。これにより、ユーザーが文字を入力するたびにリアルタイムでネットワークリクエストが送信され、$searchプロパティの値が更新され、その結果としてページ上のユーザー一覧がフィルタリングされます。

しかし問題があります： このままではページをリロードすると、検索値や検索結果が完全に失われてしまいます。共有リンクを送っても、相手に同じ検索結果を見せることができません。

この問題を解決するには、検索値をURLに保存しておく必要があります。これを実現するには、#[Url]属性を$searchプロパティの上に追加するだけです：

<?php

namespace App\Livewire;

use Livewire\Attributes\Url;
use Livewire\Component;
use App\Models\User;

class ShowUsers extends Component
{
    #[Url]
    public $search = '';

    public function render()
    {
        return view('livewire.show-users', [
            'posts' => User::search($this->search)->get(),
        ]);
    }
}

この変更を加えるだけで、ユーザーが「bob」と検索欄に入力すると、ブラウザのURLバーが自動的に更新され、次のようになります：

https://example.com/users?search=bob

この機能の素晴らしい点は、このURLを共有したり、ブックマークしたり、新しいウィンドウで開いたりすると、検索欄に「bob」が自動的に入力され、その検索条件に基づいた結果が表示されることです。つまり、ユーザー体験を損なうことなく、特定の検索状態を完全に共有できるようになります。

URLからプロパティを初期化​

#[Url]属性は双方向に機能します。つまり、この属性を付けたプロパティは：

  1. 値が更新されるたびにURLのクエリ文字列に反映される
  2. ページロード時にURLのクエリ文字列から値を読み込む

例えば、ユーザーが直接https://example.com/users?search=bobというURLにアクセスした場合、Livewireは自動的にURLから値を読み取り、$searchプロパティの初期値を「bob」に設定します。これにより、共有されたURLからページを開いたときに、正しい初期状態が表示されます。

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url]
    public $search = ''; // Will be set to "bob"...

    // ...
}

null許容プロパティ​

空の値とnullの違いを制御する

デフォルトでは、ページが?search=のような空のクエリパラメータでロードされた場合、Livewireはその値を空の文字列（""）として扱います。多くの場合はこの動作で問題ありませんが、アプリケーションによっては「値が設定されていない」ことを表すnullと「空の値が設定されている」ことを表す空文字列を区別したい場合があります。

空のクエリパラメータをnullとして扱いたい場合は、PHP の型ヒントを使って次のように実装できます：

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url]
    public ?string $search;

    // ...
}

上記のように型ヒントの前に?（クエスチョンマーク）を追加することで、そのプロパティがnull許容であることを宣言しています。この場合：

  • URLに?search=という空のクエリパラメータがある場合、Livewireは$searchの値をnullとして扱います
  • 逆に、コード内で$this->search = nullを設定した場合、URLのクエリ文字列には?search=として反映されます

これにより、「パラメータが存在するが値が空」という状態と「パラメータの値が未設定（null）」という状態を明確に区別できるようになります。

エイリアスの利用​

URLパラメータ名をカスタマイズする​

Livewireでは、URLのクエリパラメータに表示される名前をプロパティ名と異なる名前にカスタマイズできます。これには複数のメリットがあります：

  • プロパティの実際の名前を隠してセキュリティを高める
  • 短くシンプルなURLにする（例：searchをqに）
  • URLの表記を統一する（例：他のシステムとの連携時）

プロパティ名とは異なるURLパラメータ名を使うには、#[Url]属性にasパラメータを指定します：

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url(as: 'q')]
    public $search = '';

    // ...
}

これで「bob」と入力すると、URLはhttps://example.com/users?q=bobとなります。

特定の値を除外​

デフォルトでは、Livewireはプロパティの値が初期値と異なる場合にのみ、その値をクエリ文字列に含めます。これをより細かく制御したい場合は、exceptパラメータを使って特定の値をクエリ文字列から除外できます。

特に便利なのは、mount()メソッド内でプロパティの初期値を動的に設定する場合です。例えば、except: ''を指定すると、searchの値が空文字列の場合のみクエリパラメータから除外されます：

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url(except: '')]
    public $search = '';

    public function mount() {
        $this->search = auth()->user()->username;
    }

    // ...
}

exceptパラメータがない場合は、searchの値がauth()->user()->username（初期設定値）と同じになった時点でクエリパラメータから除外されます。一方、except: ''を使用すると、値が空文字列の場合のみ除外され、他のすべての値（初期設定値を含む）はクエリ文字列に表示されます。これにより、URL動作をより細かく制御できます。

ページロード時も常に表示​

デフォルトでは、Livewireはプロパティの値がページロード後に変更された場合にのみ、そのパラメータをURLに表示します。例えば、$searchプロパティのデフォルト値が空文字列（""）の場合、検索欄が空のままであればURLにはパラメータが表示されません。

しかし、値が空であっても常に?search=をクエリ文字列に含めたい場合は、#[Url]属性にkeepパラメータを設定できます：

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url(keep: true)]
    public $search = '';

    // ...
}

この設定により、ページロード時からhttps://example.com/users?search=のようにクエリパラメータが常にURLに表示されるようになります。これはフォームの初期状態を明示的に示したい場合や、URLの一貫性を保ちたい場合に便利です。

履歴への保存​

デフォルトでは、Livewireはクエリパラメータの値が変更されると、history.replaceState() APIを使ってURLを書き換えます。これは現在のブラウザの履歴エントリを新しいURLで上書きするため、ブラウザの履歴に新しいエントリは追加されません。

そのため、ユーザーがブラウザの「戻る」ボタンをクリックしても、クエリパラメータの以前の値（例えば前の?search=の値）には戻らず、完全に前のページに移動してしまいます。

もし検索の変更履歴をブラウザ履歴に保存し、「戻る」ボタンで前の検索結果に戻れるようにしたい場合は、#[Url]属性にhistoryパラメータを指定してhistory.pushStateを使用するように設定できます：

use Livewire\Attributes\Url;
use Livewire\Component;

class ShowUsers extends Component
{
    #[Url(history: true)]
    public $search = '';

    // ...
}

この設定により、検索値の変更履歴がブラウザの履歴スタックに追加されるようになります。例えば、ユーザーが検索値を「bob」から「frank」に変更した後、ブラウザの「戻る」ボタンをクリックすると、検索値（およびURL）は「bob」に戻り、対応する検索結果が表示されます。これは検索やフィルタリングを多用するアプリケーションで特に便利な機能です。

queryStringメソッドの利用​

属性ではなく、メソッドを使ってクエリ文字列の設定を定義することも可能です。この方法は、プロパティのクエリ文字列設定を動的に決定したい場合や、複数のプロパティに一括で設定を適用したい場合に特に便利です。

queryStringメソッドを使った実装例：

use Livewire\Component;

class ShowUsers extends Component
{
    public $search = '';
    public $perPage = 10;
    
    // ...

    protected function queryString()
    {
        return [
            'search' => [
                'as' => 'q',           // URLでは 'q' として表示
                'except' => '',        // 空文字列の場合はクエリに表示しない
                'history' => true,     // 履歴に追加する
            ],
            'perPage' => [
                'except' => 10,        // デフォルト値の場合はクエリに表示しない
            ],
        ];
    }
}

このメソッドを使用すると、属性と同じ機能をより集中的に管理でき、コードの見通しが良くなります。また、条件に基づいて動的に設定を変更することも可能です。

トレイトフック​

Livewireは再利用可能なトレイトからクエリ文字列の設定を追加できるトレイトフックも提供しています。これにより、共通の機能（ソート、フィルタリングなど）を複数のコンポーネントで簡単に再利用できます。

例えば、複数のコンポーネントでソート機能を提供するトレイトを作成する場合：

trait WithSorting
{
    public $sortBy = 'name';
    public $sortDirection = 'asc';
    
    // ...ソートロジック...

    // クエリ文字列のトレイトフックを定義
    protected function queryStringWithSorting()
    {
        return [
            'sortBy' => ['as' => 'sort'],            // URLでは 'sort' として表示
            'sortDirection' => ['as' => 'direction'], // URLでは 'direction' として表示
        ];
    }
}

このトレイトをコンポーネントで使用すると、自動的にソート関連のプロパティがクエリ文字列と連携します：

class ShowUsers extends Component
{
    use WithSorting; // ソート機能とクエリ文字列連携を追加
    
    // ...他のコンポーネントコード...
}

トレイトフックを使うことで、コードの重複を減らし、機能を効率的に再利用できます。
