ハイドレーション

Livewireを使うと、まるでサーバーサイドのPHPクラスを直接Webブラウザに接続しているかのように感じられます。ボタンをクリックするだけでサーバー上の関数を呼び出せるなど、この「魔法のような体験」を実現する仕組みが用意されています。しかし、実際にはこれは巧妙な「錯覚」にすぎません。

実際のLivewireは、従来のWebアプリケーションと同じ基本原理で動作しています。HTMLをブラウザに送信し、ユーザーの操作（クリックなど）を監視し、必要に応じてAJAXリクエストをサーバーに送信してサーバーサイドのコードを実行します。

Livewireがサーバーに送る各AJAXリクエストは「ステートレス」（状態を保持しない）です。つまり、サーバー側ではコンポーネントの状態を複数のリクエストにまたがって自動的に記憶する仕組みがありません。ウェブサーバーは基本的に「記憶喪失」状態なのです。そのため、Livewireは更新のたびに「このコンポーネントは現在どういう状態だったか」を毎回再現する必要があります。

これを解決するために、Livewireはサーバーサイドでコンポーネントが更新されるたびに、そのPHPコンポーネントの「スナップショット」（現在の状態を記録した写真のようなもの）を作成します。次回のリクエスト時に、このスナップショットを基にしてコンポーネントを元の状態に戻してから処理を行います。

このドキュメントでは、スナップショットを作成するプロセスを「デハイドレーション」（脱水化）、スナップショットからコンポーネントを復元するプロセスを「ハイドレーション」（水和）と呼びます。乾燥食品に水を加えて元の状態に戻すイメージに似ています。

デハイドレーション（脱水化）​

Livewireがサーバーサイドコンポーネントを「デハイドレート」する際、主に次の2つの処理を行います：

  • コンポーネントのテンプレートをHTMLに変換して表示用データを作る
  • コンポーネントの状態を保存するためのJSONスナップショットを作成する

HTMLのレンダリング​

コンポーネントが最初に表示される時や更新が発生した後、Livewireはコンポーネントのrender()メソッドを呼び出し、Bladeテンプレートを実際のHTMLに変換します。

例えば、次のようなCounterコンポーネントがあるとします：

class Counter extends Component
{
    public $count = 1;

    public function increment()
    {
        $this->count++;
    }

    public function render()
    {
        return <<<'HTML'
        <div>
            Count: {{ $count }}

            <button wire:click="increment">+</button>
        </div>
        HTML;
    }
}

初回表示や更新のたびに、LivewireはこのCounterコンポーネントを次のようなHTMLに変換します：

<div>
    Count: 1

    <button wire:click="increment">+</button>
</div>

スナップショット​

次のリクエスト時にサーバー上でCounterコンポーネントを正確に再現するために、Livewireはコンポーネントの現在の状態を捉えたJSONスナップショットを作成します。これは写真を撮るようなものです。

{
    state: {
        count: 1,
    },

    memo: {
        name: 'counter',

        id: '1526456',
    },
}

スナップショットにはmemoとstateという2つの主要部分があります：

  • memo部分：コンポーネントを識別し再作成するために必要な情報（名前やIDなど）
  • state部分：コンポーネントのすべての公開プロパティ（この例では$count）の現在の値
備考

上記のスナップショット例は簡略化されています。実際のアプリケーションでは、バリデーションエラー、子コンポーネントのリスト、ロケールなど、さらに多くの情報が含まれます。スナップショットの詳細については、スナップショットスキーマドキュメントを参照してください。

HTMLへのスナップショットの埋め込み​

コンポーネントが初めてレンダリングされる際、LivewireはこのスナップショットをJSON形式でwire:snapshotというHTML属性に埋め込みます。これにより、ブラウザ側のJavaScriptコードがこの情報を抽出して使用できるようになります：

<div wire:id="..." wire:snapshot="{ state: {...}, memo: {...} }">
    Count: 1

    <button wire:click="increment">+</button>
</div>

ハイドレーション（水和）​

例として、ユーザーがCounterコンポーネントの「+」ボタンをクリックしたとしましょう。この操作によってLivewireは以下のようなデータをサーバーに送信します：

{
    calls: [
        { method: 'increment', params: [] },
    ],

    snapshot: {
        state: {
            count: 1,
        },

        memo: {
            name: 'counter',

            id: '1526456',
        },
    }
}

Livewireがincrementメソッドを実行する前に、まずスナップショットの情報を使って新しいCounterインスタンスを作成し、前回の状態を復元する必要があります。これが「ハイドレーション」の過程です。

以下のPHP疑似コードは、この復元プロセスを示しています：

$state = request('snapshot.state');
$memo = request('snapshot.memo');

// コンポーネント名とIDからインスタンスを作成
$instance = Livewire::new($memo['name'], $memo['id']);

// スナップショットの状態からプロパティを設定
foreach ($state as $property => $value) {
    $instance[$property] = $value;
}

この処理により、Counterオブジェクトが作成され、そのプロパティ（$count）がスナップショットの値（1）に設定されます。その後でようやくincrementメソッドが呼び出され、$countが2になります。

高度なハイドレーション​

上記のCounterの例は単純な整数値（1）の処理しか示していませんが、Livewireはより複雑なデータ型もサポートしています。

例えば、Todosという複雑なコンポーネントを見てみましょう：

class Todos extends Component
{
    public $todos;

    public function mount() {
        $this->todos = collect([
            'first',
            'second',
            'third',
        ]);
    }
}

このように、$todosプロパティを文字列を含むLaravelコレクションに設定しています。

単純な配列ならJSONで表現できますが、Laravelコレクションのような特殊なオブジェクトはそのままではJSONに変換できません。そこでLivewireは、データとその型情報を一緒に保存する独自の方法を開発しました。

このTodosコンポーネントのスナップショットは次のようになります：

state: {
    todos: [
        [ 'first', 'second', 'third' ],
        { s: 'clctn', class: 'Illuminate\\Support\\Collection' },
    ],
},

普通なら次のような単純な配列を期待するかもしれませんが：

state: {
    todos: [ 'first', 'second', 'third' ],
},

このままでは、ハイドレーション時にこれが通常の配列なのか、特殊なLaravelコレクションなのかを判断できません。

そこで、Livewireは「タプル」（2つの要素からなる配列）という形式で、データとその型情報を一緒に保存します：

todos: [
    [ 'first', 'second', 'third' ],  // データ部分
    { s: 'clctn', class: 'Illuminate\\Support\\Collection' },  // 型情報
],

Livewireがコンポーネントの状態をハイドレートする際にタプルに遭遇した場合、タプルの2番目の要素に格納された情報を使用して、最初の要素に格納された状態をよりインテリジェントにハイドレートします。

より明確に示すために、上記のスナップショットに基づいてコレクションプロパティを再作成する方法を示す簡略化されたコードを以下に示します：

[ $state, $metadata ] = request('snapshot.state.todos');

$collection = new $metadata['class']($state);

ご覧のとおり、Livewireは状態に関連付けられたメタデータを使用して、完全なコレクションクラスを導出します。

ハイドレーション時に、Livewireはこの型情報を見て、データを適切なオブジェクトに変換します。この仕組みにより、Livewireは単純な値だけでなく、複雑なオブジェクトも正確に復元できるのです。

深くネストされたタプル​

この方法の利点は、複雑に入れ子になったデータ構造も処理できることです。

例えば、Todosコンポーネントを少し変更して、3番目の要素を通常の文字列ではなくLaravel Stringableオブジェクトにしてみましょう：

class Todos extends Component
{
    public $todos;

    public function mount() {
        $this->todos = collect([
            'first',
            'second',
            str('third'),
        ]);
    }
}

このコンポーネントの状態に対する脱水スナップショットは、次のようになります。

todos: [
    [
        'first',
        'second',
        [ 'third', { s: 'str' } ],
    ],
    { s: 'clctn', class: 'Illuminate\\Support\\Collection' },
],

ご覧のとおり、コレクション内の3番目のアイテムはメタデータタプルに脱水されています。タプル内の最初の要素はプレーンな文字列値であり、2番目の要素はこの文字列が_文字列可能_であることをLivewireに示すフラグです。

カスタムデータ型のサポート​

内部的に、Livewireは一般的なPHPやLaravelのデータ型を標準でサポートしていますが、独自のデータ型を扱いたい場合はSynthesizersを使用できます。これは、複雑なデータ型のハイドレーション/デハイドレーションを行うためのLivewireの拡張機能です。
