レイジーロード

Livewireでは、初回のページ読み込み速度を低下させてしまうコンポーネントを遅延読み込み（レイジーロード）できます。

例として、mount()メソッド内で重いデータベースクエリを実行するRevenueコンポーネントを考えてみましょう。

<?php

namespace App\Livewire;

use Livewire\Component;
use App\Models\Transaction;

class Revenue extends Component
{
    public $amount;

    public function mount()
    {
        // 重いデータベースクエリ...
        $this->amount = Transaction::monthToDate()->sum('amount');
    }

    public function render()
    {
        return view('livewire.revenue');
    }
}
<div>
    今月の売上: {{ $amount }}
</div>

遅延読み込みを使わない場合、このコンポーネントはページ全体の読み込みを遅らせ、結果としてアプリケーション全体が遅く感じられてしまいます。

遅延読み込みを有効にするには、コンポーネントに単にlazyパラメータを渡すだけです。

<livewire:revenue lazy />

これにより、Livewireはコンポーネントをすぐには読み込まず、一旦スキップしてページをコンポーネントなしで読み込みます。その後、コンポーネントがビューポート（画面の表示領域）に入ると、Livewireは非同期のネットワークリクエストを実行し、このコンポーネントを完全に読み込みます。

遅延リクエストはデフォルトで独立処理されます

他のネットワークリクエストとは異なり、遅延読み込みの更新は他のリクエストとまとめて送信されず、個別に独立して処理されます。これにより、ページ読み込み時に各コンポーネントが並行して読み込まれるため、全体的な遅延読み込みの速度が向上します。 この独立処理を無効にする方法については、こちらを参照してください →

プレースホルダーHTMLの表示​

デフォルトでは、Livewireはコンポーネントが完全に読み込まれるまでの間、単に空の<div></div>を表示します。これでは最初は何も見えず、コンポーネントが突然ページに表示されると、ユーザー体験の面で不自然に感じられることがあります。

コンポーネントが読み込み中であることをユーザーに視覚的に伝えるために、placeholder()メソッドを定義することで、ローディングスピナーやスケルトン表示など、任意のプレースホルダーHTMLを表示できます。

<?php

namespace App\Livewire;

use Livewire\Component;
use App\Models\Transaction;

class Revenue extends Component
{
    public $amount;

    public function mount()
    {
        // 重いデータベースクエリ...
        $this->amount = Transaction::monthToDate()->sum('amount');
    }

    public function placeholder()
    {
        return <<<'HTML'
        <div>
            <!-- ローディングスピナー... -->
            <svg>...</svg>
        </div>
        HTML;
    }

    public function render()
    {
        return view('livewire.revenue');
    }
}

上記の例では、placeholder()メソッドで「プレースホルダー」HTMLを返しているため、コンポーネントの読み込みが完了するまでの間、ユーザーにSVGローディングスピナーが表示されるようになります。

プレースホルダーとコンポーネントは同じHTML要素タイプを使用する必要があります

例えば、プレースホルダーのルート要素が<div>の場合、コンポーネント本体のルート要素も<div>である必要があります。要素タイプが一致しないと表示の問題が発生します。

Bladeビューを使ったプレースホルダーの表示​

スケルトンロードなどのより複雑なローディング表示を実装する場合は、render()メソッドと同様に、placeholder()メソッドからviewを返すことができます。

public function placeholder(array $params = [])
{
    return view('livewire.placeholders.skeleton', $params);
}

また、遅延読み込みコンポーネントに渡された任意のパラメータは、placeholder()メソッドの$params引数として利用できます。

ページ読み込み時の即時遅延読み込み​

デフォルトでは、遅延読み込みコンポーネントは、ユーザーがスクロールしてそのコンポーネントがブラウザの表示領域（ビューポート）に入るまで読み込まれません。

ビューポートに入るのを待たずに、ページ読み込み完了後すぐにコンポーネントを遅延読み込みしたい場合は、lazyパラメータに「on-load」を指定します。

<livewire:revenue lazy="on-load" />

これにより、コンポーネントはページの読み込みが完了した直後に、画面に表示されているかどうかに関わらず読み込まれます。

プロパティの受け渡し​

基本的に、遅延読み込み（lazy）コンポーネントは通常のコンポーネントと同じように扱うことができ、外部からデータを渡すこともできます。

例として、親コンポーネントからRevenueコンポーネントに日付範囲を渡すシナリオを見てみましょう。

<input type="date" wire:model="start">
<input type="date" wire:model="end">

<livewire:revenue lazy :$start :$end />

このデータは、他のコンポーネントと同様にmount()メソッドで受け取ることができます。

<?php

namespace App\Livewire;

use Livewire\Component;
use App\Models\Transaction;

class Revenue extends Component
{
    public $amount;

    public function mount($start, $end)
    {
        // 高コストなデータベースクエリ...
        $this->amount = Transactions::between($start, $end)->sum('amount');
    }

    public function placeholder()
    {
        return <<<'HTML'
        <div>
            <!-- ローディングスピナー... -->
            <svg>...</svg>
        </div>
        HTML;
    }

    public function render()
    {
        return view('livewire.revenue');
    }
}

ただし、通常のコンポーネント読み込みと異なる点として、遅延読み込みコンポーネントでは渡されたプロパティがシリアライズ（デハイドレート）され、後続のネットワークリクエスト時に再ハイドレートされる点に注意が必要です。

例えば、RevenueコンポーネントにEloquentモデルを渡す場合：

<livewire:revenue lazy :$user />

通常のコンポーネントであれば、PHPメモリ上の$userモデルがそのままRevenueコンポーネントのmount()メソッドに渡されます。しかし、遅延読み込みの場合、mount()メソッドは後続のネットワークリクエストが処理されるまで実行されません。そのため、Livewireは内部的に$userをJSONとしてシリアライズし、その後のリクエスト処理時にデータベースから再度クエリして取得します。

通常、このシリアライズ処理がアプリケーションの動作に大きな影響を与えることはありません。

コンポーネント全体をデフォルトで遅延読み込みにする​

コンポーネントをどこで使用する場合でも常に遅延読み込みするようにしたい場合は、コンポーネントクラスに#[Lazy]属性を追加します。

<?php

namespace App\Livewire;

use Livewire\Component;
use Livewire\Attributes\Lazy;

#[Lazy]
class Revenue extends Component
{
    // ...
}

このようにデフォルトで遅延読み込みに設定されたコンポーネントでも、必要に応じて個別の使用箇所で通常の読み込みに戻すことができます。その場合は、lazyパラメータをfalseに設定します。

<livewire:revenue :lazy="false" />

リクエストの独立処理を無効にする​

ページに複数の遅延読み込みコンポーネントがある場合、デフォルトでは各コンポーネントは独立した別々のネットワークリクエストを発行します。つまり、各遅延読み込みは単一のリクエストにまとめられず、それぞれ個別に処理されます。

この独立処理を無効にして、すべての更新を一つのネットワークリクエストにまとめたい場合は、isolate: falseパラメータを使用します。

<?php

namespace App\Livewire;

use Livewire\Component;
use Livewire\Attributes\Lazy;

#[Lazy(isolate: false)]
class Revenue extends Component
{
    // ...
}

これにより、例えば同じページ内に10個のRevenueコンポーネントがある場合、ページ読み込み時にすべての10個のコンポーネント更新がひとつにまとめられ、単一のネットワークリクエストとしてサーバーに送信されます。

ページ全体の遅延読み込み​

ページ全体を構成するLivewireコンポーネントを遅延読み込みしたい場合は、ルート定義で->lazy()メソッドを使用できます。

Route::get('/dashboard', \App\Livewire\Dashboard::class)->lazy();

逆に、デフォルトで遅延読み込みに設定されているコンポーネントの遅延読み込みを無効にしたい場合は、enabled: falseパラメータを使用します。

Route::get('/dashboard', \App\Livewire\Dashboard::class)->lazy(enabled: false);

グローバルなデフォルトプレースホルダービューの設定​

アプリケーション全体で共通のデフォルトプレースホルダービューを設定したい場合は、/config/livewire.php設定ファイルで指定できます。

'lazy_placeholder' => 'livewire.placeholder',

これにより、遅延読み込みコンポーネントで個別にplaceholder()メソッドが定義されていない場合、Livewireは自動的に設定されたBladeビュー（この例ではlivewire.placeholder）を使用します。

テスト時に遅延読み込みを無効にする​

遅延コンポーネントや、遅延コンポーネントを含むページをユニットテストする場合、遅延読み込み動作を無効にして最終的な表示結果を直接検証したいことがあります。遅延読み込みを無効にしない場合、テスト時にはコンポーネントがプレースホルダーとして表示されるだけになってしまいます。

こうした場合は、Livewire::withoutLazyLoading()テストヘルパーを使用することで、テスト時の遅延読み込みを簡単に無効化できます。

<?php

namespace Tests\Feature\Livewire;

use App\Livewire\Dashboard;
use Livewire\Livewire;
use Tests\TestCase;

class DashboardTest extends TestCase
{
    public function test_renders_successfully()
    {
        Livewire::withoutLazyLoading()
            ->test(Dashboard::class)
            ->assertSee(...);
    }
}

これにより、このテストにおいてダッシュボードコンポーネントがレンダリングされる際、placeholder()の表示をスキップし、あたかも遅延読み込みが全く設定されていないかのようにコンポーネントの完全な内容が表示されます。これによって実際の表示内容をテストで正確に検証できるようになります。
