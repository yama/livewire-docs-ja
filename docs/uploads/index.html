アップロード

Livewireは、コンポーネント内でファイルアップロードを強力にサポートしています。

まず、コンポーネントに WithFileUploads トレイトを追加してください。このトレイトを追加すると、ファイル入力にも他の入力と同じように wire:model を使うことができ、Livewireがアップロード処理を自動で行います。

以下は、写真のアップロードを扱うシンプルなコンポーネントの例です。

<?php

namespace App\Livewire;

use Livewire\Component;
use Livewire\WithFileUploads;
use Livewire\Attributes\Validate;

class UploadPhoto extends Component
{
    use WithFileUploads;

    #[Validate('image|max:1024')] // 最大1MB
    public $photo;

    public function save()
    {
        $this->photo->store(path: 'photos');
    }
}
<form wire:submit="save">
    <input type="file" wire:model="photo">

    @error('photo') <span class="error">{{ $message }}</span> @enderror

    <button type="submit">Save photo</button>
</form>
「upload」メソッドは予約語です

上記の例では「save」メソッドを使っていますが、「upload」という名前はLivewireで予約されているため、メソッドやプロパティ名として使用できません。

開発者の視点では、ファイル入力の扱いは他の入力と変わりません。<input>タグに wire:model を付与するだけで、あとはLivewireが処理してくれます。

ただし、ファイルアップロードの裏側では、Livewireがさまざまな処理を行っています。ユーザーがファイルを選択した際の流れは次の通りです。

  1. 新しいファイルが選択されると、LivewireのJavaScriptがサーバー上のコンポーネントに一時的な「署名付き」アップロードURLをリクエストします。
  2. URLを受け取ると、JavaScriptが実際のアップロードを行い、Livewireが指定する一時ディレクトリにファイルを保存し、新しい一時ファイルのユニークなハッシュIDを返します。
  3. ファイルのアップロードとハッシュIDの生成が完了すると、LivewireのJavaScriptがサーバー上のコンポーネントに最終リクエストを送り、対象のパブリックプロパティに新しい一時ファイルをセットします。
  4. これで、パブリックプロパティ（この例では $photo）に一時ファイルがセットされ、いつでも保存やバリデーションが可能になります。

アップロードしたファイルの保存​

前述の例は、アップロードされたファイルをアプリケーションのデフォルトファイルシステムの「photos」ディレクトリに移動する最も基本的な保存方法です。

ファイル名をカスタマイズしたり、特定のストレージ「ディスク」（例：S3）を指定したい場合もあるでしょう。

元のファイル名の取得

一時アップロードファイルの元のファイル名は、->getClientOriginalName() メソッドで取得できます。

LivewireはLaravelのファイルアップロードAPIと同じものを利用しているため、Laravelのファイルアップロードドキュメントも参考にしてください。以下によくある保存パターンの例を示します。

public function save()
{
    // デフォルトのファイルシステムディスクの「photos」ディレクトリにファイルを保存
    $this->photo->store(path: 'photos');

    // 設定済みの「s3」ディスクの「photos」ディレクトリにファイルを保存
    $this->photo->store(path: 'photos', options: 's3');

    // ファイル名を「avatar.png」として「photos」ディレクトリに保存
    $this->photo->storeAs(path: 'photos', name: 'avatar');

    // 設定済みの「s3」ディスクの「photos」ディレクトリにファイル名「avatar.png」で保存
    $this->photo->storeAs(path: 'photos', name: 'avatar', options: 's3');

    // 設定済みの「s3」ディスクの「photos」ディレクトリに「public」アクセス権で保存
    $this->photo->storePublicly(path: 'photos', options: 's3');

    // 設定済みの「s3」ディスクの「photos」ディレクトリにファイル名「avatar.png」で「public」アクセス権で保存
    $this->photo->storePubliclyAs(path: 'photos', name: 'avatar', options: 's3');
}

複数ファイルの扱い​

<input>タグに multiple 属性を付与すると、Livewireは自動的に複数ファイルのアップロードをサポートします。

例えば、$photos という配列プロパティを持つコンポーネントで、フォームのファイル入力に multiple を付けると、新しいファイルが自動的にこの配列に追加されます。

use Livewire\Component;
use Livewire\WithFileUploads;
use Livewire\Attributes\Validate;

class UploadPhotos extends Component
{
    use WithFileUploads;

    #[Validate(['photos.*' => 'image|max:1024'])]
    public $photos = [];

    public function save()
    {
        foreach ($this->photos as $photo) {
            $photo->store(path: 'photos');
        }
    }
}
<form wire:submit="save">
    <input type="file" wire:model="photos" multiple>

    @error('photos.*') <span class="error">{{ $message }}</span> @enderror

    <button type="submit">Save photo</button>
</form>

ファイルバリデーション​

Livewireでのファイルアップロードのバリデーションは、通常のLaravelコントローラーでのファイルバリデーションと同様に動作します。これによりLaravelの標準的なバリデーションルールを使用してファイルの検証が可能です。

S3の設定に関する重要な注意点

多くのファイルバリデーションルールは、検証時にファイルへの直接アクセスを必要とします。Amazon S3へ直接アップロードを設定している場合は、S3のファイルオブジェクトが適切な公開設定になっていない場合、バリデーションが失敗する可能性があるため注意が必要です。

バリデーションルールについてさらに詳細な情報は、Laravelの公式ファイルバリデーションドキュメントを参照してください。

一時プレビューURL​

多くの場合、ユーザーがファイルを選択した直後に、フォーム送信前にそのファイルのプレビューを表示したいケースがあります。これは特に画像アップロードのUIを向上させる上で重要です。

Livewireでは、アップロードファイルの ->temporaryUrl() メソッドを使用することで、簡単かつ安全にこのようなプレビュー機能を実装できます。

備考

一時URLは画像ファイルのみ対応 セキュリティ上の理由から、一時プレビューURLは画像MIMEタイプ（jpg、png、gif、webpなど）のファイルのみサポートされています。その他のファイル形式ではこの機能は利用できません。

以下の例は、画像プレビュー機能を含むファイルアップロードフォームの実装方法を示しています：

use Livewire\Component;
use Livewire\WithFileUploads;
use Livewire\Attributes\Validate;

class UploadPhoto extends Component
{
    use WithFileUploads;

    #[Validate('image|max:1024')]
    public $photo;

    // その他のメソッド...
}
<form wire:submit="save">
    @if ($photo) <!-- [tl! highlight:2] -->
        <img src="{{ $photo->temporaryUrl() }}">
    @endif

    <input type="file" wire:model="photo">

    @error('photo') <span class="error">{{ $message }}</span> @enderror

    <button type="submit">Save photo</button>
</form>

Livewireはセキュリティを考慮して一時ファイルを非公開ディレクトリに保存するため、通常であれば一時的な公開URLを簡単に発行することはできません。

しかし、この問題を解決するためにLivewireでは一時的な署名付きURLを自動的に生成し、アップロードした画像をページ上で安全にプレビュー表示できるようにしています。

このURLシステムには以下の安全対策が施されています：

  • 一時ディレクトリより上の階層のファイルへのアクセスを防止
  • 署名検証によるURL改ざん防止
  • 他のファイルプレビューへの不正アクセス防止
Amazon S3利用時の一時署名付きURL

一時ファイルの保存先をAmazon S3に設定している場合、->temporaryUrl() メソッドを呼び出すとS3の署名付き一時URLが自動的に発行されます。これにより、画像プレビュー表示時にLaravelアプリケーションサーバーを経由せず、直接S3から画像データを読み込むことができるため、サーバー負荷を軽減し、パフォーマンスを向上させることができます。

ファイルアップロードのテスト​

Laravelのファイルアップロード用テストヘルパーを使って、Livewireのファイルアップロードもテストできます。

以下は UploadPhoto コンポーネントのテスト例です。

<?php

namespace Tests\Feature\Livewire;

use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\Storage;
use App\Livewire\UploadPhoto;
use Livewire\Livewire;
use Tests\TestCase;

class UploadPhotoTest extends TestCase
{
    public function test_can_upload_photo()
    {
        Storage::fake('avatars');

        $file = UploadedFile::fake()->image('avatar.png');

        Livewire::test(UploadPhoto::class)
            ->set('photo', $file)
            ->call('upload', 'uploaded-avatar.png');

        Storage::disk('avatars')->assertExists('uploaded-avatar.png');
    }
}

次は、上記テストをパスさせるための UploadPhoto コンポーネント例です。

use Livewire\Component;
use Livewire\WithFileUploads;

class UploadPhoto extends Component
{
    use WithFileUploads;

    public $photo;

    public function upload($name)
    {
        $this->photo->storeAs('/', $name, disk: 'avatars');
    }

    // その他のメソッド...
}

ファイルアップロードのテストについては Laravelのファイルアップロードテストドキュメント もご参照ください。

Amazon S3への直接アップロード​

前述のように、Livewireはデフォルトですべてのファイルアップロードを一時ディレクトリに保存して処理します。

標準の動作​

デフォルト設定では、Livewireはアプリケーションのデフォルトファイルシステムディスク（通常は local）の livewire-tmp/ ディレクトリにすべてのアップロードファイルを一時保存します。

この標準設定では、すべてのアップロードはいったんアプリケーションサーバーを経由し、必要に応じて後からS3バケットなどの外部ストレージに保存するという2段階のプロセスになります。

S3への直接アップロード設定​

サーバー負荷を減らしたり、大容量ファイルを効率的に処理したりするために、アプリケーションサーバーを経由せずに直接S3バケットにファイルをアップロードしたい場合は、config/livewire.php 設定ファイル内で livewire.temporary_file_upload.disk の値を s3（または s3 ドライバを使用するカスタムディスク）に変更するだけで有効にできます。

return [
    // 他の設定...
    'temporary_file_upload' => [
        'disk' => 's3',
        // 他の一時ファイル設定...
    ],
];

これで、ユーザーがファイルをアップロードした際、ファイルはサーバーには保存されず、直接S3バケットの livewire-tmp/ サブディレクトリに保存されます。

Livewireの設定ファイル公開

ファイルアップロードディスクをカスタマイズする前に、以下のコマンドでLivewireの設定ファイルを /config ディレクトリに公開してください。

php artisan livewire:publish --config

自動ファイルクリーンアップの設定​

S3での自動クリーンアップの重要性​

時間が経つと、Livewireの一時アップロードディレクトリには大量の使用されないファイルが蓄積され、ストレージコストの増加やパフォーマンス低下を引き起こす可能性があります。S3を使用する場合は特に、24時間以上経過した古い一時ファイルを自動的に削除するライフサイクルポリシーを設定することが非常に重要です。

S3クリーンアップの設定方法​

Amazon S3を利用している環境では、以下の便利なArtisanコマンドを実行するだけで、必要なライフサイクル設定が自動的に適用されます：

php artisan livewire:configure-s3-upload-cleanup

このコマンドを実行すると、24時間以上経過したすべての一時ファイルがS3上で自動的に削除されるライフサイクルポリシーが設定されます。これにより、ストレージの肥大化を防ぎ、コスト効率を高めることができます。

他のストレージタイプについて

ローカルディスクや、S3以外のクラウドストレージを使用している場合は、Livewireフレームワークが自動的にクリーンアップ処理を行うため、上記コマンドを実行する必要はありません。このクリーンアップ機能はLivewireに最初から組み込まれています。

ローディングインジケーター​

簡単なアップロード状態の表示​

ファイルアップロードの際は、ユーザーに処理状況を視覚的に伝えることが重要です。ファイルアップロード用の wire:model は内部的に他の入力タイプとは異なる処理を行いますが、ユーザー体験向上のためのローディングインジケーターの実装方法は他のLivewire要素と同様にシンプルです。

以下のように、ファイルアップロード専用のローディングインジケーターを簡単に追加できます：

<input type="file" wire:model="photo">

<div wire:loading wire:target="photo">アップロード中...</div>

上記の例では、ファイルがアップロード処理中の間のみ「アップロード中...」というメッセージが表示され、アップロードが完了するとメッセージは自動的に非表示になります。これにより、ユーザーは現在の処理状態を明確に把握できます。

ローディング状態の様々な利用方法や応用例については、ローディング状態の詳細ドキュメントを参照してください。

進捗インジケーター​

リアルタイム進捗表示の実装​

大きなファイルをアップロードする場合、単純なローディング表示だけでなく、実際の進捗状況をパーセンテージやプログレスバーで表示することでユーザー体験を大幅に向上させることができます。

Livewireのファイルアップロード機能は、自動的に対応する <input> 要素上で以下のJavaScriptイベントを発火します。これらのイベントを利用することで、カスタムJavaScriptやAlpineJSを使って高度な進捗表示を実装できます。

イベント名説明
livewire-upload-startファイルアップロードが開始された時点で発火
livewire-upload-finishファイルアップロードが正常に完了した時点で発火
livewire-upload-cancelユーザーによってアップロードがキャンセルされた時に発火
livewire-upload-errorアップロード処理中にエラーが発生した時に発火
livewire-upload-progressアップロード進行中に定期的に発火（$event.detail.progressに0～100の進捗率を含む）

以下は、AlpineコンポーネントでLivewireファイルアップロードの進捗バーを表示する例です。

<form wire:submit="save">
    <div
        x-data="{ uploading: false, progress: 0 }"
        x-on:livewire-upload-start="uploading = true"
        x-on:livewire-upload-finish="uploading = false"
        x-on:livewire-upload-cancel="uploading = false"
        x-on:livewire-upload-error="uploading = false"
        x-on:livewire-upload-progress="progress = $event.detail.progress"
    >
        <!-- ファイル入力 -->
        <input type="file" wire:model="photo">

        <!-- 進捗バー -->
        <div x-show="uploading">
            <progress max="100" x-bind:value="progress"></progress>
        </div>
    </div>

    <!-- その他のフォーム要素 -->
</form>

アップロードのキャンセル​

ユーザーによるアップロード中断の実装​

大容量ファイルのアップロードには時間がかかることがあり、ユーザーが処理途中でアップロードをキャンセルしたいケースがよくあります。Livewireでは組み込みの $cancelUpload() 関数を使って、この機能を簡単に実装できます。

シンプルなキャンセルボタンの例​

以下は、wire:click を使用したキャンセルボタンの基本的な実装例です：

<form wire:submit="save">
    <!-- ファイル入力フィールド -->
    <input type="file" wire:model="photo">

    <!-- キャンセルボタン -->
    <button type="button" wire:click="$cancelUpload('photo')">アップロードをキャンセル</button>

    <!-- その他のフォーム要素 -->
</form>

「アップロードをキャンセル」ボタンをクリックすると、現在進行中のアップロードリクエストが即時に中断され、ファイル入力が自動的にクリアされます。これにより、ユーザーは別のファイルを選択して再度アップロードを試みることができます。

Alpine.jsとの連携​

AlpineJSを使用している場合は、以下のようにAlpineのイベントハンドラからLivewireのキャンセル機能を呼び出すこともできます：

<button type="button" x-on:click="$wire.cancelUpload('photo')">アップロードをキャンセル</button>

これにより、より複雑なUIインタラクションに対応したキャンセル機能の実装が可能になります。

JavaScriptアップロードAPI​

高度なアップロード制御​

より複雑なユースケースや、Dropzone.jsなどのサードパーティのファイルアップロードライブラリと連携する場合、標準の <input type="file" wire:model="..."> だけでは柔軟性が不足することがあります。

このような高度なシナリオに対応するため、Livewireは強力なJavaScript APIを提供しています。これにより、ドラッグ&ドロップインターフェース、プレビュー生成、カスタム検証など、より洗練されたファイルアップロード体験を実現できます。

これらのAPIは、Livewireコンポーネントのテンプレート内で $wire オブジェクト経由で簡単にアクセスでき、必要に応じてカスタムJavaScriptに組み込むことができます。

@script
<script>
    let file = $wire.el.querySelector('input[type="file"]').files[0]

    // ファイルをアップロード...
    $wire.upload('photo', file, (uploadedFilename) => {
        // 成功時のコールバック...
    }, () => {
        // エラー時のコールバック...
    }, (event) => {
        // 進捗状況のコールバック...
        // event.detail.progressには0から100までのアップロード進捗率が含まれます
    }, () => {
        // キャンセル時のコールバック...
    })

    // 複数ファイルをアップロード...
    $wire.uploadMultiple('photos', [file], successCallback, errorCallback, progressCallback, cancelledCallback)

    // 複数アップロードされたファイルから単一のファイルを削除...
    $wire.removeUpload('photos', uploadedFilename, successCallback)

    // アップロードをキャンセル...
    $wire.cancelUpload('photos')
</script>
@endscript

設定オプション​

Livewireのファイルアップロードシステムは、セキュリティとパフォーマンスを考慮しながら、すべてのファイルを一時的に保存してからバリデーションや最終的な保存処理を行う設計になっています。この動作をプロジェクトの要件に合わせて調整するための様々な設定オプションが用意されています。

グローバルバリデーションルールのカスタマイズ​

セキュリティを考慮して、Livewireはデフォルトですべての一時ファイルアップロードに対して file|max:12288（12MB未満のファイル）というバリデーションルールを適用します。

プロジェクトの特定の要件に合わせてこのグローバルルールを変更したい場合は、config/livewire.php 設定ファイルで以下のように定義できます：

'temporary_file_upload' => [
    // 他の設定項目...
    'rules' => 'file|mimes:png,jpg,pdf|max:102400', // (最大100MB、PNGとJPEGとPDFのみ許可)
],

アップロードエンドポイントの保護（ミドルウェア設定）​

アップロード用エンドポイントへの過剰なリクエストからサーバーを保護するため、デフォルトでスロットリングミドルウェアが適用されています。セキュリティ要件に応じてこの設定をカスタマイズすることができます：

'temporary_file_upload' => [
    // 他の設定項目...
    'middleware' => 'throttle:5,1', // ユーザーごとに1分間で最大5回のアップロードのみ許可
],

一時ファイル保存ディレクトリの変更​

アプリケーションの構成に応じて、一時ファイルの保存場所をカスタマイズしたい場合があります。デフォルトでは、指定したディスクの livewire-tmp/ ディレクトリにファイルが保存されますが、以下のように別のディレクトリを指定することも可能です：

'temporary_file_upload' => [
    // 他の設定項目...
    'directory' => 'tmp', // 'livewire-tmp/' の代わりに 'tmp/' ディレクトリを使用
],

これらの設定オプションを活用することで、アプリケーションのセキュリティ要件やパフォーマンス要件に合わせたファイルアップロード機能の最適化が可能です。
